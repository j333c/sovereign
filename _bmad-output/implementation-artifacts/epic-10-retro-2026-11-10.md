## Findings

### Aggregate Views

1. **Git-Native Update Discovery Engine & SemVer Monotonic Flooring (`aggregate:arch-delta`)**
   - *Source:* `internal/supervisor/discovery.go`, `internal/supervisor/semver.go`
   - *Observation:* To avoid GitHub REST API rate limits and external dependencies, update discovery queries the public distribution remote via `git ls-remote --tags --refs origin` over Smart HTTP. Polling is throttled to at most once per hour. A dedicated SemVer 2.0.0 parser implements monotonic upgrade evaluation ensuring candidates strictly exceed the current running version.
   - *Disposition:* Full match.

2. **Multi-Channel Settings UI & Destructive Safeguards (`aggregate:arch-delta`)**
   - *Source:* `web/src/components/settings/SystemSettingsTab.tsx`, `web/src/components/DestructiveModal.tsx`, `cmd/sovereign-daemon/handlers_auth_settings.go`
   - *Observation:* Transitioning to the Preview channel requires explicit typing of localized confirmation tokens (`PREVIEW`, `VORSCHAU`, `PRELIMINAR`, `VISTA PREVIA`, `APERÇU`), verified on both client and daemon layers. Switching back to Stable enters a calm "Graduating to Stable" holding pattern rather than performing unsupported database downgrades.
   - *Disposition:* Full match.

3. **Turnkey Installer Channel Seeding & Unattended Maintenance Pipeline (`aggregate:spec-reconciliation`)**
   - *Source:* `install.sh`, `internal/supervisor/maintenance.go`
   - *Observation:* `install.sh` accepts `--channel stable|security-only|preview`, resolves qualifying release tags using Debian version sorting, and seeds `/data/state/update_channel`. The 3:00 AM maintenance runner flushes SQLite WAL via `PRAGMA wal_checkpoint(TRUNCATE)`, takes atomic snapshots, and records overnight outcomes in SQLite.
   - *Disposition:* Full match.

4. **Upstream Spoke Dependency Governance & Release Publishing Pipeline (`aggregate:pattern-divergence`)**
   - *Source:* `docker-compose.yml`, `scripts/audit-spoke-tags.sh`, `scripts/publish-release.sh`, `scripts/verify-remotes.sh`
   - *Observation:* Caddy was pinned from floating `caddy:2-alpine` to `caddy:2.8.4-alpine`. All spoke images and supervisor constants are audited for strict SemVer or llama.cpp build tags. `scripts/publish-release.sh` automates the release lifecycle with dual-remote pushes to `origin` and `github` and verification of tag ref parity.
   - *Disposition:* Full match.

### Diff-Scope Review Lenses

1. **Adversarial Lens (`lens:adversarial`)**
   - *Source:* `cmd/sovereign-daemon/handlers_auth_settings.go:171-193`
   - *Trigger condition:* Malicious client attempting to bypass UI confirmation token when activating Preview channel.
   - *Guard snippet:* Backend inspects `confirmation_token` case-insensitively against localized valid tokens and returns HTTP 422 Unprocessable Entity if token is omitted or invalid.

2. **Edge-Case Lens (`lens:edge-case`)**
   - *Source:* `install.sh:387-393`
   - *Trigger condition:* Multiple pre-release candidates (e.g. `v1.0.0-rc.1` vs `v1.0.0-rc.10`) sorted alphabetically by GNU `sort` placing `rc.10` before `rc.2`.
   - *Guard snippet:* `sed 's/-/~/g' | sort -V | sed 's/~/-/g'` leverages Debian version sorting semantics where `~` sorts before any alphanumeric character, correctly ordering numeric pre-releases.

3. **Data-Integrity Lens (`lens:data-integrity`)**
   - *Source:* `internal/supervisor/maintenance.go:121-135`
   - *Trigger condition:* Overnight update applying while database WAL has uncommitted transactions.
   - *Guard snippet:* Calls `store.DB.FlushWAL(ctx)` executing `PRAGMA wal_checkpoint(TRUNCATE)` and writes atomic SQLite backup snapshot to `/data/state/backups/pre-maintenance-<ts>.db` before container updates.
