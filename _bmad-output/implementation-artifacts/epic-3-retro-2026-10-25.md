### Diff-Scope Review Lenses

1. **Adversarial Lens (`lens:adversarial`)**
   - *Source:* `cmd/sovereign-daemon/server.go:1091` & `cmd/sovereign-daemon/server.go:1100`
   - *Trigger condition:* `POST /api/v1/optical/eject` and `POST /api/v1/transcode/queue` are exposed without administrative session authentication.
   - *Guard snippet:* Wrap both routes with `s.requireSetupOrAdmin(s.handleOpticalEject)` and `s.requireSetupOrAdmin(s.handleEnqueueTranscode)`.
   - *Potential consequence:* Malicious or curious LAN users can repeatedly eject the physical drive tray or overload the transcoding database queue with unverified tasks.
   - *Disposition:* Fix now (Action Item 3.1).

2. **Edge-Case Lens (`lens:edge-case-hunter`)**
   - *Source:* `internal/enrichment/engine.go:210-245`
   - *Trigger condition:* If TMDb or MusicBrainz rate limits or fails with HTTP 429/500, failed albums/movies could be repeatedly re-queried on every scan tick without exponential backoff.
   - *Guard snippet:* Store `last_attempt_at` and `retry_count` in metadata staging metadata and enforce exponential backoff (e.g. 5m, 30m, 2h).
   - *Potential consequence:* Transient metadata provider outages cause log flooding and API key exhaustion.
   - *Disposition:* Fix now (Action Item 3.2).

3. **Verification Gap Lens (`lens:verification-gap`)**
   - *Source:* `internal/optical/driver_test.go:30-80`
   - *Trigger condition:* Optical drive tests mock udev / sysfs events, but do not verify behavior when the drive hardware is physically disconnected via USB during an active rip.
   - *Guard snippet:* Add test verifying `ripper.Eject()` and rip cancellation when underlying device handle encounters `EIO` (I/O error).
   - *Potential consequence:* Disconnecting an external USB optical drive mid-rip could leave staging files permanently locked.
   - *Gap shape:* `phantom-exception`
   - *Consumer:* `internal/optical/ripper.go:145`
   - *Evidence:* Zero tests assert `EIO` / device disconnection mid-stream.
   - *Disposition:* Defer (Action Item 3.3).
