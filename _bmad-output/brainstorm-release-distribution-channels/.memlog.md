- (note) Technique batch announced: 1. Decision Tree Mapping, 2. Worst Possible Idea, 3. The Blast Radius Inversion (invented), 4. The Persona Dial-In (invented)
- (note) Invented technique 1: The Blast Radius Inversion - Map out every safety layer, isolation boundary, and fallback escape hatch that renders catastrophic update failures zero-impact or self-reversing.
- (note) Invented technique 2: The Persona Dial-In - Stress-test the update pipeline, default settings, and notification models against radical home server user extremes.
- (technique) started Decision Tree Mapping
- (idea) install.sh provides `--channel stable|security-only|preview` (default: `stable`) during provisioning and CLI upgrades, seeding `/data/state/update_channel`
- (idea) Installed system provides a dropdown menu in settings to choose from update streams (`Stable`, `Security-only`, `Preview`)
- (decision) Repository git clone/fetch is the distribution vehicle; daemon checks GitHub (`origin` inside `/opt/sovereign`) at most once per hour via `git ls-remote --tags --refs origin`
- (decision) Selecting Preview channel triggers a DestructiveModal style warning confirming irreversible forward schema migration with localized `"PREVIEW"` confirmation tokens
- (decision) Unattended updates during maintenance window (3:00 AM) with pre-update snapshot & 180s health check; development on release branches; upstream spoke container versions checked and updated
- (decision) Git-native polling via `git ls-remote --tags --refs origin` avoids GitHub REST API rate limits and requires no API tokens
- (decision) Spoke container versions must be explicitly pinned (SemVer for spokes/Caddy, `^b[0-9]{4,}$` build tags for `llama.cpp`) and verified via automated upstream checks rather than floating `:latest`
- (decision) Development workflow uses `release/v<MAJOR>.<MINOR>` and `hotfix/v<MAJOR>.<MINOR>.<PATCH>` branches with `-rc.<N>` pre-release tags pushed to both `origin` and `github` remotes
